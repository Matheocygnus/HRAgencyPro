Build a full-stack web application for a Human Resources (HR) agency with three distinct user roles: Super Admin, Admin, and Recruiter. The platform must support a client-driven hiring workflow.

🧑‍💼 User Roles
Super Admin

Full access to all resources, users, and data.

Can create Admins and Recruiters.

Can manage system configurations and view reports.

Admin

Manages clients and companies.

Can review and edit data submitted by recruiters.

Approves contracts and verifies invoicing.

Recruiter

Responsible for finding, interviewing, and tracking prospects.

Manages communication with candidates.

Uploads resumes and completes candidate profiles.

💼 Main Entities
Client: A business that requests candidates. May be linked to one or more companies.

Company: The organization hiring through the platform.

Prospect: A potential candidate being evaluated.

Hero: A hired prospect.

Contract: An agreement between client and hero.

Invoice: Billing details after hiring.

📋 Workflow Logic
Client Requests a Candidate

The client fills out a request form.

Form includes company info, requirements, and contact details.

If company or client doesn't exist yet, allow creation.

Recruiter Searches for Prospects

Search manually (social media, external channels).

Prospect information is added to the system.

If the profile doesn't match the client’s requirements, stop process and save reason.

Interview & Evaluation

Schedule and log interview with prospect.

Recruiter presents matching profiles to the client.

Client can approve or reject.

Client Decision

If rejected, stop the process and save data.

If approved, proceed to the next step.

Budget Agreement

Check if both client and candidate agree on compensation.

If not, stop the process and log rejection.

If yes, proceed to contract generation.

Hire and Finalize

Generate contract, sign digitally.

Create new "Hero" record.

Trigger automated actions:

Generate Deel account (placeholder logic).

Create invoice.

Store contract and invoice in respective tables.

⚙️ Backend Requirements
Authentication system with role-based access control.

Relational database (e.g., PostgreSQL or similar) with these tables:

Users

Clients

Companies

Prospects

Heroes

Contracts

Invoices

Boolean fields to track each decision stage (e.g., approved, interviewed, matched).

📲 UI Requirements
Dashboard per user role:

Recruiter: Candidates pipeline, forms to add/edit prospects, status tracking.

Admin: Approvals list, contracts management, company/client registry.

Super Admin: System-wide stats, user management.

Notifications and alerts for pending actions (e.g., missing info, interview coordination).

Form interface for every action: new client, new prospect, contract generation, etc.
